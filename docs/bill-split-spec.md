# 一日の割り勘ツール仕様

## 1. 目的

飲み会の1軒目、2軒目、3軒目など複数の会計を店舗ごとに割り勘し、最後に一日分の負担額と、立替情報が揃っている場合は最終精算をまとめて確認、コピーできるようにする。

Party Deckは金銭を預からず、送金、決済、請求、支払い完了管理を行わない。扱うのは端末内の計算結果とコピー用テキストだけとする。

## 2. 基本方針

- 割り勘はゲームではなく、ホームの `便利ツール` として提供する。
- `GameId`、`GameRegistry`、ゲームセッションへ追加しない。
- 既存のプレイヤー名と担当色を再利用する。
- 1つの「一日の割り勘」に複数の店舗会計を追加できる。
- 参加者と負担割合は一日共通にせず、店舗ごとに設定する。
- 一日の負担額は、各店舗で確定した1円単位の金額を単純合算する。
- 店舗の割合を一日全体へ再適用しない。
- 金額はすべて整数の日本円として扱う。
- バックエンド、アカウント、電話番号、決済ID、口座情報は使わない。

## 3. 対象範囲

### 初期実装に含める

- 一日の割り勘の開始、再開、終了
- 店舗会計の追加、編集、削除
- 店舗名または `1軒目` などの表示名
- 店舗ごとの合計金額
- 店舗ごとの参加者選択
- 店舗ごとの `少なめ 0.5`、`通常 1.0`、`多め 1.5`
- `少なめ` の任意理由
- 1円単位で合計が一致する割合計算
- 同順位の端数対象者のランダム抽選
- 店舗ごとの結果表示とコピー
- 一日分の負担額合計とコピー
- 店舗ごとの立替者1人の任意登録
- 全店舗に立替者が設定されている場合の最終精算表示とコピー
- 48時間以内の端末内復元

### 初期実装に含めない

- 実際の送金、決済、請求リンク生成
- 支払い済みチェック、督促、通知
- 1店舗を複数人で立て替えるケース
- レシート撮影、OCR、品目単位の分割
- 0.5、1.0、1.5以外の自由な割合
- 税、サービス料、クーポンの個別計算
- 複数端末での同期
- 過去の割り勘履歴一覧

## 4. 用語

| 用語 | 意味 |
| --- | --- |
| 一日の割り勘 | 複数の店舗会計をまとめる1つのローカルセッション |
| 店舗会計 | 1軒目、2軒目など1回の会計 |
| 負担割合 | 店舗内でその人が負担する比率。0.5、1.0、1.5のいずれか |
| 負担額 | 割合計算後にその人が本来負担する金額 |
| 立替額 | 店舗で実際に立替者が支払った合計金額 |
| 精算差額 | `立替額合計 - 負担額合計` |

## 6. 一日の割り勘概要画面

### 表示内容

- タイトル `今日の割り勘`
- 登録済み店舗会計のカード
- 現在の会計総額
- `会計を追加` ボタン
- `一日の合計を見る` ボタン
- `今日の割り勘を終了` ボタン

店舗カードには次を表示する。

- 店舗名
- 合計金額
- 参加人数
- 立替者。未設定なら `立替者なし`
- `結果を見る`
- `編集`
- `削除`

店舗が0件の場合は空状態を表示し、`会計を追加` を主操作にする。店舗が1件以上ある場合だけ `一日の合計を見る` を有効にする。

店舗削除時は、確定済みの計算結果も消えることを確認してから削除する。

## 7. 店舗会計入力画面

### 7.1 店舗名

- 任意入力
- 未入力の場合は追加順から `1軒目`、`2軒目`、`3軒目` を表示名として確定する
- 前後の空白を除去する
- 最大40文字

### 7.2 合計金額

- 必須
- 1円以上の整数
- 日本円のみ
- 入力UIは `inputMode="numeric"`
- 表示時は3桁区切りを付ける
- 内部では文字列入力を検証してから安全な整数へ変換する
- `Number.isSafeInteger` を満たさない値は受け付けない

### 7.3 参加者

- 既存プレイヤーを設定順で表示する
- 新規店舗の初期状態は全員参加、全員 `通常 1.0`
- 店舗ごとに参加、不参加を切り替えられる
- 計算には2人以上の参加が必要
- 不参加者は割合設定、計算結果、店舗別コピーへ含めない

### 7.4 負担割合

参加者ごとに次のどれか1つを選ぶ。

| UI表示 | 値 | 主な用途 |
| --- | ---: | --- |
| 少なめ | 0.5 | 飲んでいない、途中参加、途中退出 |
| 通常 | 1.0 | 通常参加 |
| 多め | 1.5 | 多めに負担する人 |

割合は店舗ごとに保持する。例えば同じ人が1軒目で0.5、2軒目で1.0、3軒目で不参加でもよい。

1人に複数の割合を重ねない。`少なめ` と `途中参加` を同時に選んで0.25にする動作は行わない。

### 7.5 少なめの理由

`少なめ 0.5` を選んだ場合だけ、次の任意理由を選択できる。

```ts
type ReducedShareReason = "non-drinker" | "late-join" | "early-leave" | "other";
```

表示ラベル:

- 飲んでいない
- 途中参加
- 途中退出
- その他

理由は説明とコピー用であり、計算結果には影響しない。理由未選択でも計算できる。

### 7.6 立替者

- 店舗ごとに参加者から1人を任意選択する
- `あとで決める` を許可する
- 立替者には店舗合計の全額を立替額として記録する
- 不参加者は立替者に選択できない
- 立替者を不参加へ変更した場合は立替者選択を解除する

立替者がなくても店舗別の負担計算と一日の負担額合計は利用できる。最終精算は全店舗に立替者が設定されるまで表示しない。

### 7.7 計算ボタン

次の場合は `このお店を計算` を無効にする。

- 合計金額が無効
- 参加者が2人未満
- 参加者の割合に無効な値がある
- 計算処理中

## 8. 店舗単位の割合計算

### 8.1 基本計算

参加者 `i` の割合を `weight[i]`、店舗合計を `totalYen` とする。

```ts
const totalWeight = participants.reduce((sum, participant) => sum + participant.weight, 0);
const exactAmount = totalYen * weight / totalWeight;
const floorAmount = Math.floor(exactAmount);
const fraction = exactAmount - floorAmount;
```

まず全員へ `floorAmount` を割り当て、残った円を小数部分が大きい人から1円ずつ追加する。これは最大剰余方式とする。

```ts
const remainingYen = totalYen - sum(floorAmounts);
```

### 8.2 端数のランダム抽選

1円を受け取る優先順位は小数部分の降順とする。ただし小数部分が同じ参加者同士の順位はランダムに決める。

均等割りでは全員の小数部分が同じになるため、余った1円を受け持つ人はランダムになる。

割合割りでは、数学的に負担額へ近い人を優先し、同じ条件の人だけをランダムにする。これにより `0.5`、`1.0`、`1.5` を含む場合も丸め誤差を最小化する。

ランダム処理は可能なら `crypto.getRandomValues()` を使う。テストでは乱数源を注入できる純粋関数にする。

### 8.3 抽選の固定

- 抽選は `このお店を計算` を押したときに1回だけ行う
- 計算後は各人の確定金額をstateへ保存する
- React再描画、コピー、概要画面への移動では再計算しない
- リロード後も保存済みの確定金額を復元する
- 編集画面で金額、参加者、割合を変更して再計算した場合だけ新しい結果を作る
- 結果画面に端数だけの `再抽選` ボタンは置かない

### 8.4 計算例

10,000円を `1.0 / 1.0 / 0.5` で分ける場合:

```text
アオイ  1.0  4,000円
ミナト  1.0  4,000円
ユイ    0.5  2,000円
```

10,000円を3人の均等割りにする場合:

```text
アオイ  1.0  3,333円
ミナト  1.0  3,334円  端数 +1円
ユイ    1.0  3,333円
```

3,001円を `1.5 / 1.0 / 0.5` で分ける場合、正確な割合額を基準に最大剰余方式で合計3,001円へ合わせる。

## 9. 店舗結果画面

### 表示内容

- 店舗名
- 店舗合計
- 立替者。未設定の場合は未設定表示
- プレイヤー名、担当色、割合、負担額
- `少なめ` の理由
- 追加の1円を受け持った場合の `端数 +1円`
- `このお店の結果をコピー`
- `編集`
- `一覧へ戻る`

表示順は元のプレイヤー設定順を維持する。端数抽選のために表示順をシャッフルしない。

### 店舗別コピー形式

```text
【Party Deck 割り勘・1軒目】
合計：10,000円
立替：アオイ

アオイ：4,000円（通常）
ミナト：4,000円（通常）
ユイ：2,000円（少なめ・飲んでいない）
```

端数がある場合:

```text
※割り切れない1円は割合に沿って配分し、同じ条件の場合はランダムに決めました。
```

立替者が未設定の場合は `立替：未設定` とする。

## 10. 一日の集計

### 10.1 負担額合計

各店舗で確定済みの負担額をプレイヤーIDごとに合算する。

```ts
dayShare[playerId] = sum(bill.share[playerId].amountYen);
```

一日全体の割合から再計算してはならない。店舗ごとの確定結果を足すだけとする。

不参加だった店舗は0円として扱う。1店舗以上に参加した人だけを一日の結果へ表示する。

### 10.2 整合条件

```ts
sum(dayShares) === sum(billTotals)
```

店舗追加、編集、削除後は一日の集計を再生成する。ただし、変更していない店舗の端数抽選結果は変えない。

### 10.3 負担額合計の表示例

```text
【Party Deck 一日の割り勘】
1軒目・居酒屋：12,000円
2軒目・カラオケ：8,000円
合計：20,000円

アオイ：6,667円
ミナト：6,667円
ユイ：2,000円
レン：4,666円
```

## 11. 最終精算

### 11.1 表示条件

すべての店舗会計に立替者が設定されている場合だけ表示する。1件でも未設定の店舗がある場合は、負担額合計だけ表示し、次の案内を出す。

```text
最終精算を出すには、すべてのお店で立替えた人を選んでください。
```

### 11.2 精算差額

```ts
paidTotal[playerId] = sum(bill.totalYen where bill.payerId === playerId);
net[playerId] = paidTotal[playerId] - dayShare[playerId];
```

- `net > 0`: 受け取る金額
- `net < 0`: 支払う金額
- `net === 0`: 精算不要

### 11.3 支払い指示

支払う人と受け取る人の残額を突き合わせ、合計が一致する支払い指示を生成する。初期実装では金額の大きい順に突き合わせる貪欲法でよい。

```text
ユイ → アオイ：2,000円
レン → アオイ：3,333円
レン → ミナト：1,333円
```

これはコピー用の計算結果であり、送金を実行しない。

### 11.4 最終精算コピー形式

```text
【Party Deck 一日の最終精算】
合計：20,000円

ユイ → アオイ：2,000円
レン → アオイ：3,333円
レン → ミナト：1,333円

内訳
アオイ：負担6,667円 / 立替12,000円
ミナト：負担6,667円 / 立替8,000円
ユイ：負担2,000円 / 立替0円
レン：負担4,666円 / 立替0円
```

## 12. コピー操作

- `navigator.clipboard.writeText()` を優先する
- 成功後はボタン文言を一時的に `コピーしました` へ変更する
- コピー失敗時はコピー対象テキストを選択できるフォールバックUIを表示する
- コピー操作で計算、抽選、保存内容を変更しない
- Web Share APIは初期実装の必須要件にしない

## 13. 状態モデル

```ts
type BillSplitWeight = 0.5 | 1 | 1.5;

type BillSplitParticipant = {
  playerId: string;
  nickname: string;
  color: string;
  weight: BillSplitWeight;
  reducedReason?: ReducedShareReason;
};

type BillSplitShare = BillSplitParticipant & {
  amountYen: number;
  receivedRemainder: boolean;
};

type BillSplitBill = {
  id: string;
  label: string;
  totalYen: number;
  payerId: string | null;
  participants: BillSplitParticipant[];
  shares: BillSplitShare[];
  createdAt: string;
  updatedAt: string;
};

type BillSplitDay = {
  version: 1;
  id: string;
  startedAt: string;
  updatedAt: string;
  bills: BillSplitBill[];
};
```

計算結果にはプレイヤー名と色のスナップショットを保持する。店舗計算後にプレイヤー設定が変更されても、確定済み店舗の表示とコピー結果は自動変更しない。

## 14. 保存と期限

保存先:

```text
party:v1:bill-split-day
```

- `localStorage`へ保存する
- タブを閉じても同じ日の2軒目、3軒目で再開できる
- `updatedAt`から48時間を超えたデータは読み込み時に破棄する
- `今日の割り勘を終了` で確認後に削除する
- 一度に保持する一日の割り勘は1件だけとする
- 不正、旧version、壊れたJSONは破棄して新規状態へ戻す

## 15. 広告

割り勘の概要、入力、店舗結果、一日結果には広告を表示しない。

初期実装では `BillSplit` feature内で `AdSlot` を使わない。将来広告方針を変更する場合も、金額入力や精算結果の誤操作を起こさないことを優先する。

## 17. 必須テスト

### 店舗計算

- 12,540円を4人の1.0で分けると全員3,135円になる
- 10,000円を3人の1.0で分けると1人だけ3,334円になる
- 10,001円を3人の1.0で分けると2人だけ3,334円になる
- 10,000円を `1.0 / 1.0 / 0.5` で分けると `4,000 / 4,000 / 2,000` になる
- `0.5 / 1.0 / 1.5` の割合に沿って計算される
- 店舗内の負担額合計が店舗合計と一致する
- 同率端数対象者数が不足しない
- 同一人物へ同じ丸め処理で複数の1円を誤配分しない
- 再描画、コピー、画面移動で確定結果が変わらない
- 不参加者が計算とコピーへ入らない
- 参加者が2人未満なら計算できない

### 一日集計

- 店舗ごとに異なる参加者と割合を設定できる
- 店舗ごとの確定額をそのまま合算する
- 一日の負担額合計が全店舗の合計と一致する
- 1店舗を編集しても他店舗の端数結果が変わらない
- 店舗削除後に一日の集計から除外される

### 最終精算

- 全店舗に立替者がある場合だけ最終精算を表示する
- 受取額合計と支払額合計が一致する
- 支払い指示実行後の全員の差額が0円になる
- 立替者が不参加になった場合は立替者設定を解除する

### 保存とコピー

- リロード後も店舗と確定結果を復元する
- 48時間を超えたデータを復元しない
- 終了操作で保存データを削除する
- 画面表示額とコピー内容が一致する
- クリップボード失敗時にフォールバックを表示する

## 18. 完了条件

- スマホ幅で店舗追加から一日の結果コピーまで操作できる
- 1軒目と2軒目で異なる参加者、割合、立替者を設定できる
- 各店舗と一日全体で金額合計が1円単位まで一致する
- 端数抽選が意図しない再描画で変化しない
- リロードして2軒目、3軒目を追加できる
- 金額、参加者、負担割合、立替者以外の個人情報を要求しない
- 割り勘画面に広告を表示しない
- `npm run smoke`、`npm run test`、`npm run typecheck`、`npm run build` が通る
- iPhone SafariとAndroid Chromeのスマホ幅でコピー操作を確認する
