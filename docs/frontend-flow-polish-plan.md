# 友人プレイテスト前 UI・ゲームフロー磨き計画

## 目的

公開済みMVPを、初見の友人がスマホ1台を回すだけで迷わず遊べる状態へ仕上げる。

この計画は `Frontend App Builder` の観点で、見た目だけではなく「画面状態ごとの迷い」「秘密情報の漏れ」「結果の納得感」「スマホ幅の押しやすさ」を中心に改善する。

## 前提

- ログイン、個人情報、端末位置情報は使わない。
- 最大8人、ニックネームと担当色のみ。
- 1台のスマホを順番に受け渡して遊ぶ。
- 参考元ゲームの進行、勝敗条件、採点構造には寄せる。
- ルール本文、カード文面、お題、画像、音声、UIデザインはParty Deck用に自作する。
- ゲーム追加時に干渉しないよう、ゲーム固有stateと共通UIを分ける。

## Frontend App Builderの使い方

今回は新規アプリの全面デザインではなく、既存MVPの体験改善として使う。

使う観点:

- 主要画面を状態ごとに棚卸しする。
- スマホ幅で「次に何を押すか」が一目で分かるか確認する。
- 見た目の統一より先に、ゲーム進行と秘密保護を優先する。
- 画面ごとに、主役の情報を1つに絞る。
- 受け渡し、秘密確認、回答、投票、結果の共通パターンを揃える。

必要になったら後続で画像コンセプトを作るが、現時点では既存UIを磨く方が優先。

## 優先順位

### P0: 実機で壊れる可能性があるところを潰す

対象:

- iPhone Safari
- Android Chrome
- 390px前後のスマホ幅
- 8人プレイ
- 低速回線でのGuessr画像表示

やること:

- トップから各ゲームsetupまで確認する。
- 初期3ゲームを結果まで通す。
- 追加6ゲームから最低2本を結果まで通す。
- 秘密表示、投票、回答中に戻る/リロードして秘密が漏れないか確認する。
- コンソールエラーと横スクロールを確認する。

完了条件:

- 実機でボタンが押せない、文字が読めない、秘密が戻れて見える、画像失敗で詰む、のいずれもない。

### P1: トップとsetupを「選ぶだけ」にする

目的:

- 初見でゲーム選択に迷わないようにする。
- ルール説明を読みすぎなくても開始できるようにする。

やること:

- トップの表示は、ゲームタイトル、ゲーム内容、参加人数に絞る。
- アイコンは意味が伝わるものだけ使い、意味が弱い人型アイコンは置き換える。
- setup画面は全ゲームで「タイトル」「短いルール」「詳しいルール折りたたみ」「開始設定」に揃える。
- 戻るボタンは左上固定に統一する。
- 「ゲーム一覧へ」は最終結果だけに置く。

完了条件:

- 友人がトップを見て、遊びたいゲームと必要人数を10秒以内に把握できる。

### P2: 初期3ゲームを友人テスト品質にする

#### 日本マップ当て

やること:

- 地点画像に都道府県、緯度経度、内部sequenceなどの答えヒントを出さない。
- 画像を動かせるなら操作感を明確にし、動かせないなら文言を消す。
- 回答地図は、未選択時はピンなしにする。
- ピンを刺した後のボタン文言は「回答確定」に統一する。
- 確認画面を挟まず、その地点で回答を確定する。
- 正解画面では正解地点から各回答へ線を引き、色とリストを対応させる。
- 画像取得失敗時に代替地点へ切り替える導線を用意する。切り替えは初回回答前に限定し、回答済みプレイヤーがいる場合は再試行だけにする。
- 画像が表示できるまで回答地図へ進めないようにする。

完了条件:

- 1地点、全員回答、結果確認、もう一度遊ぶ、まで迷わず進む。

#### ナンバートーク

やること:

- 数字は1から100固定、手札は1つを維持する。
- 「会話」の項目は「会話時間」として扱う。
- 「小さいと思う順に並べる」の次は結果へ直行する。
- 結果では成功/失敗の理由、崩れた箇所、正しい順を見せる。
- 結果後は「もう一度遊ぶ」を主導線にする。

完了条件:

- 数字公開から結果まで、余計な確認画面なしでテンポよく終わる。

#### ワンナイト人狼

やること:

- 役職を自由に選べる状態を維持する。
- 役職アイコンは文字だけでなく、役職らしい抽象アイコンにする。
- 役職説明は「夜にすること」「議論で考えること」「勝利条件への影響」に分ける。
- 夜の行動は役職順ではなく人名順で回す。
- 夜行動がない人にも確認画面を出し、役職を推測できないようにする。
- 投票結果と勝敗理由を最終役職ベースで分かりやすく表示する。

完了条件:

- 夜の画面を横から見られても、次の人の役職が分からない。

### P3: 追加6ゲームの「簡略化した理由」を画面とdocsに揃える

対象:

- ワード潜入者
- インサイダー推理
- スパイロケーション
- 価値観メーター
- ランキング回答
- エセアーティスト

やること:

- 参考元に寄せる部分と、スマホ1台向けに簡略化する部分をdocsに明記する。
- 公開候補、質問順、失敗トークン、描画順など、進行に必要な情報を画面へ出す。
- 秘密表示と投票UIは共通パターンへ寄せる。
- 秘密投票中は戻るボタンを出さず、受け渡しから投票へ一方向に進める。
- 最終結果では、勝敗/成功失敗の根拠を必ず表示する。

完了条件:

- 各ゲームが「なぜこの画面になるのか」を結果まで説明できる。

### P4: 共通UIを増やしすぎず整理する

目的:

- ゲーム追加で `App.tsx` がさらに肥大化しないようにする。

やること:

- setup、受け渡し、秘密表示、投票、タイマー、結果アクションを共通componentへ寄せる。
- ゲーム固有の判定ロジックは `src/games/<game>.ts` に置く。
- 追加テーブルゲームの画面は `src/features/AddedTableGames.tsx` から、必要に応じて小分けする。
- CSSは共通パターンとゲーム固有パターンを分ける。

完了条件:

- 新しいゲームを追加するとき、既存ゲームのstateやUIを直接触らずに追加できる。

### P5: QAと友人プレイテスト

自動確認:

- `npm run smoke`
- `npm run typecheck`
- `npm run build`
- `git diff --check`

ブラウザ確認:

- 390 x 844
- 430 x 932
- トップ、プレイヤー設定、各setup
- Guessr、ナンバートーク、ワンナイト人狼を結果まで
- 追加6ゲームから最低2本を結果まで
- コンソールエラーなし

友人テストで見ること:

- ルール説明なしで開始できるか。
- 誰に渡すか迷わないか。
- 秘密が漏れそうな瞬間がないか。
- 結果を見て何が起きたか分かるか。
- もう一度遊びたいゲームがあるか。
- 逆に説明が長すぎる画面がないか。

### P6: 後片付けしてpush

やること:

- 仮文言、デバッグ表示、使われていないCSSを削除する。
- docsとtask-listを更新する。
- 変更差分を確認する。
- smoke/typecheck/buildを通す。
- Browserでスマホ幅を確認する。
- 問題なければpushする。

完了条件:

- ローカル確認とVercel反映後確認の両方で、トップと初期3ゲームが動く。

## 今回やらないこと
