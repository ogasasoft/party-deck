# UI・本家フロー準拠改善計画

## 目的

公開済みMVPを、友人が説明なしでも遊びやすく、かつ参考元ゲームの進行に近い体験へ寄せる。

この計画は、2026-06-04に `Frontend App Builder` の観点とブラウザ実機相当確認で見つけたUI/フロー差分を、実装可能な順番へ落としたもの。

## 方針

優先するもの:

- 1台のスマホを回す体験が迷わない。
- 秘密情報、前プレイヤーの回答、投票内容が漏れない。
- 参考元ゲームの進行、役職構成、勝敗条件、採点方法にできるだけ寄せる。
- UI表示文言、ルール説明、お題、カード文面、画像、音声、見た目はParty Deck用に自作する。
- 結果画面だけに「ゲーム一覧へ」を置き、途中画面は次に何をするかに集中させる。
- 後からゲーム追加できるよう、ゲームごとのstateと画面を混ぜない。

優先しないもの:

- 参考元のルールブック本文、カード文面、お題リスト、UIデザインの転載。
- アカウント、オンライン同期、個人情報、位置情報許可。
- AdSense本番有効化。フロー改善が先。

## 現状確認メモ

確認環境:

- Vite dev server: `http://127.0.0.1:5173/`
- Browserプラグイン
- モバイル幅: 390 x 844

見えたこと:

- トップ画面は大きな破綻なし。ただし10ゲーム表示では一覧性がやや弱い。
- ゲームsetupは「短いルール + 詳しいルール折りたたみ」へ寄っている。
- 日本マップ当てはデッキ選択なし、No Move固定、1ラウンド相当の流れになっている。
- 日本マップ当ての地点画像内メタ情報に `東京都` が表示されており、答えのヒント漏れになっている。
- 日本マップ当ての結果地図は正解と回答の関係が見えるが、スマホでは線が弱く読み取りづらい。
- ナンバートークは「会話時間」表記、並び順から結果へ直行、結果後の「もう一度」ができている。
- ナンバートークの秘密表示中に戻るボタンがあり、前プレイヤーの数字へ戻れる可能性がある。
- ワンナイト人狼は役職選択、役職説明、投票、勝敗判定まである。
- ワンナイト人狼の夜行動が「アオイ / 占い師」のように始まるため、画面を見た人に役職が特定されやすい。
- 追加6ゲームはMVPとして動くが、一部は参考元の体験より簡略化されている。

## 優先順位

### P0: 秘密漏れと答え漏れを先に直す

理由:

- パーティゲームでは、1回でも秘密が漏れるとゲームが壊れる。
- 見た目の改善よりも先に、遊びの成立条件を守る。

対象:

1. 日本マップ当ての地点画像から都道府県など答えヒントになるメタ情報を消す。
2. 秘密表示画面の戻る動作を整理する。
3. ワンナイト人狼の夜行動を役職順表示ではなく、人名順の受け渡しに変更する。
4. リロード/ブラウザバック後に秘密表示へ直接戻らないことを再確認する。

完了条件:

- Guessr回答中に都道府県、緯度経度、内部sequenceなどのヒントが見えない。
- 秘密表示中に戻っても、前プレイヤーの秘密を見られない。
- 人狼の夜行動中、次に渡す相手以外の役職が画面から推測できない。
- `npm run smoke`、`npm run typecheck`、`npm run build` が通る。

### P1: 初期3ゲームの本家フロー寄せ

対象:

- 日本マップ当て
- ナンバートーク
- ワンナイト人狼

#### 日本マップ当て

維持する仕様:

- 日本のみ。
- デッキ選択なし。
- No Move固定。
- 1ゲーム1地点。
- 全員が同じ地点を順番に回答。
- 結果後は「もう一度」または「ゲーム一覧へ」。

改善すること:

- 地点画像カードから答えヒントになるメタ情報を削る。
- 画像がドラッグ可能に見える場合は、実際に左右確認できるか、できないなら文言を消す。
- 地図は最初からピンが刺さっている印象を弱め、ユーザーが置いた感を出す。
- 結果地図で正解地点から各回答への線を太く、色分けし、凡例またはリストと対応させる。
- 画像取得失敗時は同じラウンドで代替地点へ切り替える導線を作る。

#### ナンバートーク

維持する仕様:

- 数字は1から100固定。
- 手札は1人1枚。
- お題カテゴリは通常、変化球、恋愛。
- 数字を直接言わず、会話して、小さい順に並べる。
- 並び順から結果へ直行する。

改善すること:

- 秘密表示中の戻る動作を安全化する。
- お題カテゴリとお題品質を友人テスト後に見直す。
- 結果画面で「成功/失敗」の理由が一目でわかるよう、正しい昇順との差分を強調する。

#### ワンナイト人狼

維持する仕様:

- 3から8人。
- 使用カードはプレイヤー数+2枚。
- 中央カードは2枚。
- 役職数は自由に調整できる。
- 基本役職は村人、人狼、占い師、怪盗。
- 怪盗交換後の最終役職で勝敗判定する。

改善すること:

- 夜行動を人名順の受け渡しにする。
- 各プレイヤーの画面では、本人だけが自分の役職と可能な行動を見る。
- 夜行動がない役職にも「この人の夜確認」画面を通し、行動有無から役職が推測されないようにする。
- 人狼が仲間確認する画面も、他人から見て人狼だと分からない導線にする。
- 画面上は人名順で回すが、内部解決は占い師、人狼、怪盗の順に寄せる。怪盗の交換は夜の最後に `playerCurrentCards` へ反映する。
- 役職アイコンを文字だけでなく、役職らしい抽象アイコンへ寄せる。
- 役職説明に「夜にすること」「議論で言えること」「勝利条件への影響」を分けて表示する。
- 役職追加は、基本フロー安定後に行う。

### P2: 追加6ゲームの本家フロー寄せ

追加6ゲームは動いているが、参考元の体験に近づけるなら次の順で直す。

#### 1. ランキング回答

理由:

- 現状でも遊べるが、参考元の協力ゲームらしい失敗トークン/ライフの体験が弱い。

改善すること:

- キャプテン選択とラウンド進行をより明確にする。
- プレイヤー数に応じた失敗トークンを表示する。実装では開始時の人数分に補正する。
- 数字公開時に、順番が崩れた箇所と失ったトークンを見せる。
- 5ラウンド終了、またはトークン0で最終結果へ進む。

#### 2. 価値観メーター

理由:

- 現状は協力簡略版。参考元に寄せるならチーム戦、親、隠し正解位置、左右予想、得点レースの扱いを決める必要がある。

改善すること:

- まず「スマホ1台向け簡略協力版」で行くか「チーム戦準拠」に寄せるか決める。
- 簡略協力版なら、親の秘密確認、ヒント、相談、回答、得点の演出を強化する。
- チーム戦準拠なら、2チーム、親チーム、相手チームの左右予想、10点先取を追加する。

決定:

- 友人テスト前は簡略協力版を磨く。
- チーム戦準拠は後続タスクにする。

#### 3. ワード潜入者

改善すること:

- 公開候補ワード一覧を表示する。
- 多数派は正解ワード、潜入者は候補一覧だけを見る形にする。
- ヒントは1人1語の順番を強調する。
- 潜入者が最多票の場合、公開候補から秘密語を当てる最終推理にする。
- 潜入者が同票最多に含まれるだけでは捕まった扱いにせず、単独最多票の場合だけ最終推理へ進める。

#### 4. スパイロケーション

改善すること:

- 公開場所候補リストを用意する。
- 質問順、現在の質問者、次の回答者を見せる。
- 告発は「告発対象を選ぶ → 全員投票 → 結果」の儀式を明確にする。
- 告発投票は告発対象を除外し、対象以外の全員一致で成立させる。
- 時間切れ時はスパイが公開場所候補から場所を選ぶ。

#### 5. インサイダー推理

改善すること:

- マスターは公開役職として扱う。
- マスターと内通者だけが答えを見る。
- 質問タイマーは5分を基本にする。
- 答えが出たあと、内通者探しの議論と投票へ切り替わったことを強く見せる。
- 答えが出なかった場合の失敗条件を結果で明確にする。

#### 6. エセアーティスト

改善すること:

- 出題者/GMを1人割り当てる。
- GMはお題を知るが、描画と投票に参加しないフローにする。
- 偽物側は偽物 + GM。偽物が単独最多票でなければ捕まっていない扱いにする。
- 描画順、1筆ルール、2周終了、投票、偽物の最終推理を画面上で迷わないようにする。

決定:

- 本家フローとの差分が大きかったため、友人テスト前から人間GM方式へ寄せる。
- GMのお題作成自体はアプリが行い、GMは描画と投票に参加しない進行役として扱う。

### P3: 共通UIと見た目の整理

目的:

- ゲームが増えても、画面の操作感を揃える。
- 友人が初見で「次に誰へ渡すか」「いま何をすればいいか」を迷わないようにする。

改善すること:

- setup画面の構造を全ゲームで揃える。
- ルールは「タイトル」「短い説明」「詳しいルール折りたたみ」に統一する。
- 左上戻るボタンの表示ルールを統一する。
- 秘密表示中の戻るは、前の秘密へ戻れない専用挙動にする。
- 受け渡し画面は大きく人名を出し、次に何を見るかだけを表示する。
- 役職、カテゴリ、場所などのアイコンをゲームごとに抽象アイコンへ寄せる。
- 結果画面のアクションは「もう一度」「ゲーム一覧へ」に統一する。
- スマホ幅でカード、ボタン、長い日本語がはみ出さないようにする。

- 秘密phaseのリロード復帰smoke
- ゲーム別の開始から結果までのsmoke

ブラウザ確認:

- トップ、プレイヤー設定、各setup。
- Guessrを結果まで。
- ナンバートークを結果まで。
- ワンナイト人狼を結果まで。
- 追加6ゲームから最低2本を結果まで。
- コンソールエラーなし。

実機QA:

- iPhone Safari。
- Android Chrome。
- 4人で初期3ゲーム。
- 8人でプレイヤー設定、受け渡し、秘密表示。
- 低速回線でGuessr画像表示。

### P5: 後片付け

実装後に必ず掃除すること:

- `App.tsx` に増えたゲーム固有処理を棚卸しする。
- 共通化できる受け渡し、秘密表示、投票、タイマー、結果表示を整理する。
- 使われていない型、関数、CSS、データを削除する。
- 仮文言、デバッグ表示、調査用コメントを残さない。
- docsとtask-listを更新する。
- `git diff --check` を通す。

## Definition of Done

この改善計画全体の完了条件:

- 初期3ゲームと追加6ゲームで、秘密漏れにつながる戻る/リロード/表示がない。
- 初期3ゲームはユーザー要望どおりの簡略本家フローで最後まで遊べる。
- 追加6ゲームは、意図的な簡略化と未対応差分がdocsに明記されている。
- 結果画面以外に不要な「ゲーム一覧へ」がない。
- スマホ幅で主要画面に横スクロール、文字はみ出し、ボタン押下困難がない。
- `npm run smoke`、`npm run typecheck`、`npm run build` が通る。
- 実装後の掃除タスクが完了、または明示的に後続タスク化されている。
